# 自動塗りの実操作確認（2026-10-27）

## 実施条件

`HGS_c012_si.pman` を `build/ui-autopaint-review.pman` に複製し、現在のソースで起動した。設定も `build/ui-review-config` に分離した。元プロジェクトへの保存は行っていない。

レイヤー A、34 コマ目を見本として、画面の「自動で塗る」から残り 36 セルを実行。その後 31 コマ目と見本を同じ 305% の拡大率で切り替えて比較した。

## 実画面で確認した問題

- 見本の両頬はピンクで、ベージュの輪郭はない。31 コマ目では右頬の輪郭がベージュ、左頬と口が透過背景の緑になった。ユーザー画像と同じ問題を再現した。目や首にも原色線が残る。
- 見本の頬をスポイトで採取すると `#FFDFD4`。通常バケツで左頬を塗れた。右頬の誤った輪郭も同色で置換できた。少なくともこの例では、バケツの領域取得そのものより、色と対応先の決定が主な問題。
- 見本選択画面は全身の縮小表示で、顔の細部を拡大比較できない。「表示サイズ」はカードの大きさを変えるだけ。
- 実行対象のセルや領域を絞って試す操作が見当たらず、見本を選ぶと残り全セルの計算になる。
- 結果一覧の先頭に、背景の 3,067,727 画素が「塗り残し」として現れた。背景と修正対象が同列に並び、実際の頬・目を見つけにくい。
- 修正は見本と対象を行き来し、スポイトとバケツを切り替える必要がある。修正した領域を明示的な正解として他のセルに伝える操作がない。

## コードで確認した判定の限界

`auto_trace.palette/candidates` は元の TP 線色と隣接する大きな面の色で仕上げ候補を集計する。同じ線色・肌色に接する線を、頬・服の縁などの部位で区別しない。候補が一つなら局所照合を省略して採用する経路もある。このため「周囲の大面積と違う色」という条件だけでは、別用途の色を除外できない。

この実操作だけでベージュの採取元となった特定の領域までは追跡できていない。判定根拠が保存・表示されないため、画面から確かめられないこと自体が問題。採取元を特定したと断定しない。

## 優先する機能

1. **対応先と採色元の可視化**：対象をクリックすると、見本の採取領域・候補色・判断理由を同倍率で並べる。面と TP 線の判断をそれぞれ確認できること。
2. **領域単位の正解指定と再利用**：見本の頬と対象の頬を対応づける、または手修正を確定する。同じ元線色を持つ全領域への一律置換ではなく、部位の対応として記録する。再実行で手修正を上書きしない。
3. **現在セル／選択範囲の試し塗りと差分確認**：全セルへ進む前に顔だけ試す。結果を確認して適用・取り消しできる。範囲は通常バケツを維持する。
4. **実用的な確認一覧**：外周に接する透過背景を通常の塗り残しから分離する。顔などの切り抜き、色の違い、未確定理由、修正済み状態を表示し、前後の問題箇所へ移動できる。

改善の合格条件は原色の残数だけではない。見本と対象の頬・目・口・髪・装飾を拡大して比較し、別部位の色が入っていないこと、手修正が次の処理へ正しく反映されることを確認する。

今回は実操作による調査と課題の整理まで。上記機能の実装完了や、頬の判定エンジン修正完了を意味しない。

## 追試と判定修正

後続の検証で、31 コマ目の右頬の採色経路を追跡した。対象の緑 TP 線は 118 画素、内側のピンクは 361 画素。従来の「大きな面」の閾値は最大 256 画素に制限されていたため、ピンクも禁止色に含まれていた。元線での直接照合は正しい `#FFDFD4` を返していたにもかかわらず、候補フィルターがそれを拒否した。残った `#C9B683` の用例は見本の衣装部分（例：画像座標 `(1080,846)-(1217,907)`）にあった。

左頬は別問題だった。対応位置の見本の初期領域が複数に分かれ、どの単一領域も一致率を満たさない。しかし原色線を除いた 168 サンプルのうち 158 が頬のピンクだった。口では、初期線の切れ目で肌と口が一つの領域になっていたが、位置合わせした 119 サンプルのうち 118 が正しい口色 `#FFB09F` だった。

ソースに以下を追加し、バケツの塗り範囲を変えずに比較した。

- 隣接する最大の面の 25% に満たない面は、大きな周辺面として仕上げ色を禁止しない。外側の肌に比べて小さい頬色を候補に残す。
- 単一の初期領域で照合できない透明面には、位置合わせした完成色の照合を追加。元線を除いて対象画素の 55% 以上を採取でき、90% 以上が同色、対応する完成領域への逆方向の重なりが 50% 以上、面積比が既存上限以内の場合だけ採用する。原色線や黒線の範囲は変更しない。

見本 34 → 対象 28 / 31 / 37、見本 1 → 対象 4 の四組を、従来・周辺面のみ修正・両方修正で比較した。31 は両頬、口、首の線が改善。28 の右頬、37 の左頬と口、4 の見えている頬も改善した。28 の左頬、37 の右頬、目の原色残りは未解決であり、全セルの正解を検証した結果ではない。

比較画像・計測値は `build/cheek-comparison.png` / `build/cheek-comparison.json`、31 コマ目の前後比較は `build/cheek31-before-after.png`。単発の CPU 比較ではおおむね 0.2〜0.4 秒/セルの追加時間があった。繰り返し計測による性能保証ではない。

頬の内側の色を禁止しないこと、初期ハッチングで分断された同色面を塗れること、無関係な大きな面を小さな対象へ転用しないことの回帰テストを追加。自動塗り・バケツ・位置合わせの関連テスト 102 件が通過した。上記の UI 機能は引き続き未実装。

## TPパレットの先行作成と部位の引き継ぎ

選択見本の初期TP線の画素を、完成見本の同じ座標の色と照合して色表を先に作る。形の一致は集計に使わない。見本1・34・109から集計した主要な用例は以下のとおり。

| 元TP色 | 仕上げ色 | 見本の画素数 |
| --- | --- | ---: |
| 緑 `#00FF00` | ベージュ `#C9B683` | 1,929 |
| 緑 `#00FF00` | 頬のピンク `#FFDFD4` | 382 |
| 赤 `#FF0000` | ハイライト `#FFF7D3` | 1,595 |
| 赤 `#FF0000` | 頬の斜線 `#F0A7A0` | 158 |
| 赤 `#FF0000` | 目の白 `#FDFDFD` | 69 |
| 青 `#0000FF` | 首の色 `#E6A09E` | 75 |

透明・原色・黒は色表に含めず、合計6画素未満のまれな色は一般化する候補から除く。局所的に直接照合できた細い線については、既存の見本の文脈に実例がある少数画素の色も引き続き使える。色表・周辺文脈・囲みの用例は人が選んだ見本から一度だけ作り、自動塗りの結果から候補を追加しない。ベンチマークJSONの `tp_palette` で集計を確認できる。

候補が一つなら、同じ形が見つからなくてもTP線の仕上げ色を選べる。複数なら、周囲の大面積の色を除外し、直接対応や確定した内側の小面で区別する。「元TP線と内側の小面が同じ仕上げ色」の用例も見本から学習する。この用例があり、対象の小面の周囲に十分な長さの同用途の確定TP線が接している場合だけ、未塗りの内側も同色で塗る。単なる斜線の色を隣接面へ拡大しない。

部位の引き継ぎでは、自動で色を決めた画素のマスクを各見本に保持する。ここでの「部位」はバケツで区切られた領域であり、顔・髪などの名前の分類ではない。すぐ隣のセルが未完成でも、近傍4セル以内の追加2セルから確定部分を探せる。小面は線の一致60%、確定画素65%、既知色の一致95%以上に加え、面積比と逆方向の対応を確認する。大面は線の一致40%、確定画素80%、色の一致98%以上の場合に限って成長させる。未確定画素は答えに数えず、近い見本同士で色が割れている面も上書きしない。

見本34・対象6セルの試験段階では、19・22の左頬を形状照合なしで埋められ、25のスカート左右の引き継ぎも改善した。比較画像は `build/palette-parts-face-detail.png` / `build/palette-parts-clothes-detail.png`。新しい用途の囲みを捏造しないこと、途中の未完成セルを越えて確定部分を参照できること、未確定画素を使わないこと、自動結果が見本の色表を汚染しないことを回帰テストで確認した。バケツによる塗り範囲は維持している。

最終版を全37セルの並びで比較した。見本1・34・109は保持し、残り34セルをCPUで1巡した結果は以下。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 背景を除く透明残り | 5,654,092画素 | 3,776,031画素 |
| 原色TP線の残り | 8,703画素 | 8,582画素 |
| 計算と比較画像出力の合計時間 | 109.534秒 | 141.089秒 |

透明残りは約33%減った一方、TP線そのものの減少は小さい。パレットを作るだけでは複数候補の用途が不明な場所は解決しないことも確認できた。見本34だけの試験で埋まった19・22の左頬は、3見本を使う比較では候補が割れて残った。色を強制して埋めた結果ではなく、未解決箇所を含む比較である。時間は各1回のCPU計測であり、処理負荷などの影響を含む（このスクリプトでは画像出力も計測区間に含まれる）。

`build/palette-full-results.json` が集計、`build/palette-full-comparison.png` が25・49・79・94の全身比較。全対象34セルの黒線画素が変化していないことも確認した。関連テスト190件、変更した処理と計測スクリプトの型チェック・Ruffが通過している。今回の実装はパレットと部位引き継ぎの処理であり、パレット編集画面や部位名の認識を追加したものではない。

## 未塗りセルを越える部位の追跡

`auto_part_tracking.py` に、確定部分の空間索引と線画の変形追跡を追加した。以前は直近4セルの追加2見本だけを調べていたが、確定部分の索引を残し、未塗りセルを越えて最大12セルの経路をたどれる。候補は対象領域の近くに確定画素がある上位3セルに絞り、別のセルが未完成になっても過去の成功を削除しない。

離れた見本へ一度で合わせるのではなく、間のセルの元線画を使って隣接セル間の動きを合成する。元線画の動きは32画素区画の流れで求め、逆向きの流れも計算する。逆写像が同じ一点へ戻ることは要求せず、元の部位の内側・輪郭に戻ることを確かめる。無地の長い線に沿う移動と、別の部位へ飛ぶ誤対応を区別するためである。

輪郭全体の一致だけでなく四分割した各方向にも対応があること、黒線とTP線の種類が合うことを確認する。内側は70%以上の既知画素と95%以上の色の一致が必要。小面では対応先の面積も確かめる。滑らかな動きでは合わない近傍2セルまでの部位は、64画素（非常に大きい面は96画素）の小区画を個別に照合し、往復で同じ部位へ戻り、区画全体で色がそろうときだけ採色する。これらは色とクリック位置を決める処理であり、塗る範囲は元の通常バケツの領域をそのまま使う。

見本1・34・109、全37セルの同じ条件で対象34セルをCPUで1巡した比較では、背景を除く透明残りが **3,776,031 → 2,684,584画素（さらに約29%減）**。原色TP線の残りは8,582画素で変わらない。衣装、腕、髪の一部で引き継ぎが進んだが、19コマ目などの大きな髪の残りは未解決。処理とPNG出力込みの単発時間は141.089 → 167.634秒だった。結果は `build/tracking-full-results.json`、40・70・79・94の比較は `build/tracking-full-comparison.png`、70だけの比較は `build/tracking70-before-after.png`。

未塗り6セルを越えた参照、せん断変形、未確定画素と複数色の拒否、動きの往復、キャッシュの再利用、バケツ範囲の保持をテストした。自動塗り・バケツ・線画の動きの関連215テスト、型チェック・Ruffが通過。Rustを無効にしたNumPy経路でも新しい6テストが通過した。対象6セルでは実GPUで982回の位置合わせを行い、CPUとの出力フィンガープリント一致も確認した。CPUとGPUの計測は並行実行のため、その時間から速度差は評価していない。

背景の追加検査では、通常バケツの背景領域上で変更前後に1,069画素の差があった。すべて画面下端へ延長した仮想境界の補完画素であり、隣接する面のバケツにも含まれる範囲だった。仮想境界の補完画素を除いた背景成分には、対象34セルを通じて差がないことを確認した。黒線画素も全対象で保持されている。
