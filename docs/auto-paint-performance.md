# 自動塗りの処理と計測

自動塗りは、対象の初期線画に対して通常のバケツと同じ設定で領域を求める。
見本が塗るマスクを作ることはない。塗る位置・色は `CellPaint.clicks` に残す。

高速化は自動塗り1回の中で完結する。別のプロジェクトや編集後の画像に結果を流用しない。

- `BucketSession(indexed=True)` は、バケツの前処理で得た探索可能な画素を4近傍で
  番号付けする。仮想境界上のクリックは従来の探索へ戻し、隙間回収・含み塗り・島の
  置換は通常のバケツ処理を通す。結果のキャッシュは32 MiB、前処理は4色まで保持する。
- 対象の領域一覧は最初の回に作り、矩形内のマスクだけを保持する。
- 線画の位置合わせは、対象・見本の境界と矩形・探索幅が同じ場合に再利用する。
  色が変わっても線が同じなら再計算しない。
- 色の再判定は、対応する見本の面の色または未決定フラグが変わった場合に行う。
  変わらない面も新しい見本との対応確認は行うため、新しく使える見本を見落とさない。

## 塗り残しを増やさないための照合

元の線画同士を比較する場合は、重ねた先の線上の画素を面の投票から除く。
残った画素の72%以上が同じ面に入り、見本側の面の50%以上を覆うこと、面積比が
3倍以内であることを確かめる。これにより、面が伸縮しただけで90%の一致条件から
落ちることを避ける。色を決めるときは、対応先の面全体の90%以上が一色である条件を保つ。

元の線画がない代替経路では、仕上げ色の境界で対応を判断してしまう可能性があるため、
従来の90%・逆方向75%の条件を維持する。未決定の面を確定色として扱うこともしない。
TP線は元の線画の同じ線色を半径2画素の範囲で照合する。対象線の75%以上が対応し、
見本の一本の線へ90%以上が対応し、その線の45%以上を異なる画素で覆う必要がある。
塗るマスクは通常のバケツが決めたままで、見本の形や色の境界を転写しない。

## TP線の仕上げ

面を先に塗り、TP線は別のバケツ操作として仕上げる。自動塗りでは含み塗りと島の
一括置換を無効にし、隣接した同色の領域をクリックする。非隣接や不透明全体の設定で
実線の境界を消したり、面の色でTP線まで塗りつぶしたりしない。手動バケツの設定は変更しない。

見本の初期TP線と完成画像から「元の線色・周囲の大きな面の色・仕上げ色」を学習する。
人が選んだ全見本の仕上げ規則は、直接の形合わせから離れたセルにも共有する。
塗り進めたセルで線の根拠が少なくなっても、元の見本の仕上げ色を失わない。
周囲の大きな面と同色の候補、黒・透明・原色は仕上げ色として採用しない。
大きな面は原画上で接する面の面積と、完成画像での主な色から判定する。

線の位置を照合できればその色を優先する。線の形が変わっていても、同じ初期線色の
近傍サンプルや、周囲の面の色がよく一致する学習例から仕上げ色を選ぶ。
文脈のない用例が、周囲の面が一致する用例を妨げることはない。
学習に必要な根拠がある場合は1〜2画素のTP線も対象とする。候補が割れる場合や見本に
置換色の根拠がない場合は未決定として残し、周囲の面の色で埋めない。

## GPU（任意）

CUDA 13対応のNVIDIA GPU・ドライバーがある開発環境では、次で任意依存を入れる。
通常の起動にGPUライブラリは必要ない。配布実行ファイルに自動で含まれるわけではない。

```bash
python -m pip install -e ".[gpu]"
```

GPUで処理するのは位置合わせのFFTだけ。サイズを64画素単位にまとめ、同じサイズの
バッチで実行する。戻すのは候補位置の表だけで、画像全体を往復させない。
FFTプランのメモリーはGPU総容量の1/16または512 MiBの小さい方まで、バッチの入力は
通常16 MiB程度までに制限する。

既定の `auto` は対象が4セル以上、画像が65,536画素以上の場合に一括GPU処理を試す。
同じサイズにまとめられる位置合わせが4件未満の場合はCPUで処理する。サイズごとにCPUとGPUを
計測し、GPUが15%以上速く、CPUと同じ位置を選ぶ場合に以後のバッチに使用する。
僅差・閾値付近の判断、GPUが使えない場合、実行エラーの場合はCPUへ戻る。
初回のCUDA初期化・コンパイルには時間がかかるため、短い処理にはCPUを使う。

`PMA_AUTO_PAINT_GPU=off` でCPUのみ、`on` で少数セルでもGPUの一括処理を試せる。
`on` の場合も、計測で遅かったサイズや判断の際どい箇所にはCPUを使う。

## 再現可能な計測

```bash
python -m scripts.benchmark_auto_paint project.pman \
  --frames 1,4,7,10,13 --references 1 --gpu auto --repeats 3 --output benchmark.json
```

フレーム番号は1始まり、`--layer` は0始まり（既定1）。画像の読み込みと線の抽出は
時間計測の外、領域作成・位置合わせ・色選択・塗り計画の作成は計測の中にある。
入力プロジェクトには書き込まない。最初の試行も表示し、GPU初期化の費用を隠さない。

JSONには各試行の時間、描画結果・クリック・未決定範囲の指紋、位置合わせのCPU/GPU
件数、再利用した色判定の件数を出す。変更前のモジュールを保存したディレクトリーが
あれば、開発用の `--snapshot` 引数で同じデータを旧実装でも計測できる。

## 30秒を目標にした追加計測（2026-10-27）

この段階では30秒は未達。HGS_c012_siの37セル、見本1・34・109、対象34セルで、変更後のCPUは75.837秒、既定のGPU autoは78.602秒だった。読み込みとPNG保存を除いた塗り計画の時間。最大3巡を指定したが、このデータは既存の終了条件で1巡で終了する。3巡を強制的に1巡へ減らして短縮した結果ではない。いずれも1回の計測であり、環境の揺れを含む。

変更前のCPUプロファイルでは170.749秒、そのうちFFT相関59.083秒、TP線近傍の小面の採色18.137秒だった。変更前はプロファイラー有効のため、変更後の通常計測と厳密な倍率比較はしない。以前のPNG保存込み167.634秒とも測定範囲が違う。

実装した短縮:

- FFTは探索する±marginに必要なゼロ余白だけを取り、2・3・5の積で表せる寸法に広げる。使わない遠方の相関を求めず、素数の大きな寸法も避ける。ランダム画像で従来の全相関の候補窓との一致を検査した。
- 通常の隣接バケツで隙間回収や含み塗りが不要な面は、既存の連結成分索引の矩形からCompactFillを作る。全キャンバスマスクの作成・複製を省く。隙間回収・含み塗り・島の置換・特殊な対象指定は従来経路に戻す。
- 同じpainted画像の小面の最多色は、そのセルのTP線処理中だけ共有する。異なる塗り結果へ流用しない。
- 多数決で最初の値が厳密な過半数を占める場合はソートせず確定し、それ以外は従来の集計へ戻す。連結領域の色もラン作成時に保持する。
- 小面のずれ探索は、探索範囲内に面積比を満たす領域が全くない場合だけ省く。
- 隣接線画の往復変形のキャッシュを12組から64組に増やし、この例の再計算を106組から36組へ減らした。

CPU・GPUとも、変更前の塗り画像・クリック・未決定領域を含むフィンガープリント `5d0ec9486572f45dc08d7bb88a35003e14eaffcb0d7d0a61ebdb4ea268d1c4f8` と一致。未塗り判定の閾値や画像解像度は下げていない。GPU autoは実際に9,210件のFFTをGPUへ渡したが、全体ではCPUを上回らなかった。GPUプロファイルでは領域準備・対応先のバケツ領域・採色などのCPU処理が残っている。30秒に向けては、この部分の一括化・ネイティブ化をさらに行う必要がある。

集計: `build/autopaint-speed-baseline.json`、`build/autopaint-speed-cpu.json`、`build/autopaint-speed-final.json`。関連218テストと領域・参照塗りの追加27テストが通過。変更した自動塗り関連モジュールとreference_checkの型チェック、Ruffが通過。bucket_fill全体の型チェックには、今回変更していない箇所のOptional型の指摘が7件残る。

## 領域判定・採色のRust化（2026-10-27）

`native/src/auto_paint.rs` に以下を追加した。塗るマスクや判定の閾値を変えず、既存のNumPy経路も残している。新しいAPIのない旧部品や `PMA_NO_NATIVE=1` では従来経路へ戻る。

- 走査線の上下の連結判定と領域番号の割り当て。NumPyと同じ最小ルート・初出順の番号を返す。
- 小画像の走査・連結・番号画像作成の一括処理。大画像は転送と出力の複製が重いため、NumPyでの走査とRustでの結合を併用する。実素材の2320×1480画像で、boolの全Rust走査18.0msに対して併用12.1ms、packed色値では25.9msに対して13.5msだった（5回の中央値）。全Rust走査を試した全体61.727秒も採用していない。
- 小面の最大121位置の採色、多数決、未決定画素の拒否、逆方向の面積比を小矩形の転送1回で処理する。
- 不変の見本を横方向のランへ圧縮して保持するGuideSampler。重なり・最多色・対応する領域の面積・未確定画素・同点時の最小値・一致画素の中央のクリック位置を、区間の長さで集計する。大面の全画素の座標配列を毎回作らない。採色、通常面の照合、確定部位の引き継ぎに使用する。

圧縮見本の再利用は、計画中に色・元線画・未決定フラグ・確定マスクを設定し終えた_Cellに限る。通常の可変_Cellは再利用せず、フラグを変更した後も反映する。Rust側はPythonのオブジェクトを保持せず、純粋な計算中はGILを解放する。

同じ素材の見本1・34・109、対象34セル、CPU・最大3巡の逐次単発比較では、従来処理76.060秒→Rust処理57.332秒（約25%減）。画像の読み込み・PNG保存は含まない。従来比較は今回追加した4つの入口だけを無効にし、以前からのRust細線化・膨張・線画追跡は有効のままにした。この素材は既存の終了条件でどちらも1巡で終わる。30秒は未達。

変更前後のフィンガープリントは `5d0ec9486572f45dc08d7bb88a35003e14eaffcb0d7d0a61ebdb4ea268d1c4f8` で一致し、描画結果、クリック、未決定領域を保持している。集計は `build/auto-rust-fair-before.json` と `build/auto-rust-full.json`。比較用入口は `build/benchmark_before_auto_rust.py`。

release wheelをオフラインでビルドし、`.venv` のRust部品へ導入した。起動中のアプリは旧DLLを読み込んでいるため、反映には再起動が必要。配布exeは更新していない。

既定のGPU autoでも全34対象セルを検証し、60.380秒、GPU位置合わせ9,226件で同じフィンガープリントを確認した（`build/auto-rust-full-gpu.json`）。各1回の計測であり、今回はCPUのみの方が速かった。

最終検証はPython関連284件、Rust既存9件が通過。追加したRust・NumPyの突き合わせ19件には、異なる整数幅・符号・byte order・小数値のフォールバック、ランと領域番号、可変フラグ、色の混在、確定画素の不足、画面外のずれ、最多値の同点と中央のクリック位置、不正な入力を含む。`PMA_NO_NATIVE=1` でも関連26件が通過（Rust専用18件はスキップ）。型チェックとRuffが通過し、追加Rustファイルはrustfmtに適合。cargo clippyも完了し、新規ファイルの指摘はなく、既存unique_colorsのスタイル指摘2件と環境のハードリンク警告は残る。
