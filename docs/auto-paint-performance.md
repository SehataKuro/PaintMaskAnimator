# 自動塗りの処理と計測

自動塗りは、対象の初期線画に対して通常のバケツと同じ設定で領域を求める。
見本が塗るマスクを作ることはない。塗る位置・色は `CellPaint.clicks` に残す。

高速化は自動塗り1回の中で完結する。別のプロジェクトや編集後の画像に結果を流用しない。

- `BucketSession(indexed=True)` は、バケツの前処理で得た探索可能な画素を4近傍で
  番号付けする。仮想境界上のクリックは従来の探索へ戻し、隙間回収・含み塗り・島の
  置換は通常のバケツ処理を通す。結果のキャッシュは32 MiB、前処理は4色まで保持する。
- 対象の領域一覧は最初の回に作り、矩形内のマスクだけを保持する。
- 線画の位置合わせは、対象・見本の境界と矩形・探索幅が同じ場合に再利用する。
  色が変わっても線が同じなら再計算しない。
- 色の再判定は、対応する見本の面の色または未決定フラグが変わった場合に行う。
  変わらない面も新しい見本との対応確認は行うため、新しく使える見本を見落とさない。

## 塗り残しを増やさないための照合

元の線画同士を比較する場合は、重ねた先の線上の画素を面の投票から除く。
残った画素の72%以上が同じ面に入り、見本側の面の50%以上を覆うこと、面積比が
3倍以内であることを確かめる。これにより、面が伸縮しただけで90%の一致条件から
落ちることを避ける。色を決めるときは、対応先の面全体の90%以上が一色である条件を保つ。

元の線画がない代替経路では、仕上げ色の境界で対応を判断してしまう可能性があるため、
従来の90%・逆方向75%の条件を維持する。未決定の面を確定色として扱うこともしない。
TP線は元の線画の同じ線色を半径2画素の範囲で照合する。対象線の75%以上が対応し、
見本の一本の線へ90%以上が対応し、その線の45%以上を異なる画素で覆う必要がある。
塗るマスクは通常のバケツが決めたままで、見本の形や色の境界を転写しない。

## TP線の仕上げ

面を先に塗り、TP線は別のバケツ操作として仕上げる。自動塗りでは含み塗りと島の
一括置換を無効にし、隣接した同色の領域をクリックする。非隣接や不透明全体の設定で
実線の境界を消したり、面の色でTP線まで塗りつぶしたりしない。手動バケツの設定は変更しない。

見本の初期TP線と完成画像から「元の線色・周囲の大きな面の色・仕上げ色」を学習する。
人が選んだ全見本の仕上げ規則は、直接の形合わせから離れたセルにも共有する。
塗り進めたセルで線の根拠が少なくなっても、元の見本の仕上げ色を失わない。
周囲の大きな面と同色の候補、黒・透明・原色は仕上げ色として採用しない。
大きな面は原画上で接する面の面積と、完成画像での主な色から判定する。

線の位置を照合できればその色を優先する。線の形が変わっていても、同じ初期線色の
近傍サンプルや、周囲の面の色がよく一致する学習例から仕上げ色を選ぶ。
文脈のない用例が、周囲の面が一致する用例を妨げることはない。
学習に必要な根拠がある場合は1〜2画素のTP線も対象とする。候補が割れる場合や見本に
置換色の根拠がない場合は未決定として残し、周囲の面の色で埋めない。

## GPU（任意）

CUDA 13対応のNVIDIA GPU・ドライバーがある開発環境では、次で任意依存を入れる。
通常の起動にGPUライブラリは必要ない。配布実行ファイルに自動で含まれるわけではない。

```bash
python -m pip install -e ".[gpu]"
```

GPUで処理するのは位置合わせのFFTだけ。サイズを64画素単位にまとめ、同じサイズの
バッチで実行する。戻すのは候補位置の表だけで、画像全体を往復させない。
FFTプランのメモリーはGPU総容量の1/16または512 MiBの小さい方まで、バッチの入力は
通常16 MiB程度までに制限する。

既定の `auto` は対象が4セル以上、画像が65,536画素以上の場合に一括GPU処理を試す。
同じサイズにまとめられる位置合わせが4件未満の場合はCPUで処理する。サイズごとにCPUとGPUを
計測し、GPUが15%以上速く、CPUと同じ位置を選ぶ場合に以後のバッチに使用する。
僅差・閾値付近の判断、GPUが使えない場合、実行エラーの場合はCPUへ戻る。
初回のCUDA初期化・コンパイルには時間がかかるため、短い処理にはCPUを使う。

`PMA_AUTO_PAINT_GPU=off` でCPUのみ、`on` で少数セルでもGPUの一括処理を試せる。
`on` の場合も、計測で遅かったサイズや判断の際どい箇所にはCPUを使う。

## 位置合わせを依存段階ごとに一括処理（2026-10-27）

採色中に位置合わせが不足した場合は、その採色を保留して要求を集め、同じ段階の要求をまとめて解く。解けなかった箇所の追加照合も次の段階にまとめる。採色の再実行で触るのは対応領域・色判定のキャッシュだけとし、クリックや塗り範囲の確定は従来の順序で行う。面・部位からの引き継ぎ・曖昧なTP線が対象。重複する要求は境界画像と矩形のキーで除外する。

区画追跡は「1区画の全往復を終えてから次の区画」から、「全区画を1セルずつ進める」構造に変更した。往路の失敗区画は以降の探索から除外し、成功した区画だけを復路でもまとめる。切り詰めた矩形、累積移動、復路の検証、採色の集計順序は保つ。

CPUでは4件以上の要求を計画全体で共有する最大4スレッドに振り分ける。FFTの入力は実行中のスレッド内で作るため、全要求分の大きなFFT画像を保持しない。キャッシュへの書き込みは主スレッドで行う。正常終了・中止・例外時には計画のExitStackでスレッドを回収する。既存GPUの先行処理・数値検証経路は保持する。
