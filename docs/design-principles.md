# 設計方針

機能を足したり UI を変えたりするときに前提とする方針です。
「なぜそうしないのか」を残しておき、同じ議論を繰り返さないためのメモです。

## 原画の作業には対応しない

PaintMaskAnimator は **動画以降の工程**（動画・仕上げ）を行うツールとして設計します。
原画の作業（原画番号の管理、原画から動画への番号の振り直しなど）はこのツールの対象にしません。

**理由**

- 原画と動画では、セル番号の体系がまるごと置き換わります。原画は原画ごとの番号に
  中割り指定（「・」、ア・イ・ウ、逆シート指定など）が付き、動画になると通し番号に
  振り直されます。
- 両方の工程を 1 つのツールで扱うと、番号の付け方・並べ替え・逆シートの扱いが
  すべて二重になり、作業の流れもデータ構造も大幅に複雑になります。

**このため**

- 原画やタイムシートの中割り指定は、外部から受け取る **参照用の情報** として扱います。
  編集の対象にはしません。
- セル番号は動画番号だけを持ちます。原画番号から動画番号へ振り直す仕組みは作りません。

## セル番号は整数の連番だけにする

セル（絵）の番号は **1 から始まる整数** だけを認めます。
`1.5` のような小数や、`ア`・`イ` のようなカナ、`2'` のような記号付きの番号は使いません。

**理由**

- After Effects などの読み込み先では、整数以外の番号を正しく扱えません。
- 連番タイムライン（連番モード）は、番号が整数で順に並んでいることを前提にしています。

**このため**

- 既存のキーフレームの間に新しい絵を足した場合でも、整数の番号を付けます。
- 番号の順番とタイムライン上の登場順がずれたときは、「番号の正規化」
  （タイムラインの順番で振り直す）で揃えます。
- 新しく足した絵には、既存の番号を変えずに済むよう **末尾の番号**（最大の番号＋1）を付けます。
  後ろの番号を繰り下げる方式は採りません。

### 撮影済みのカットでは正規化しない

撮影済みのカットをリテイクで直し、中割りを足す場合は、番号の正規化をしてはいけません。
足した絵は末尾の番号のままにします。

**理由**

- AE ではすでにタイムリマップを打っています。足したところ以外の番号が変わると、
  同じ番号が別の絵を指すようになり、撮影データと食い違います。
- たとえば A4 が表す絵は、リテイクの前後で同じでなければなりません。

正規化の確認画面には、この注意を必ず表示します。

## 将来は Rust へ置き換えていく

PaintMaskAnimator は、将来的に Rust へ置き換えていく方針です。
ただし一度に全部を書き直すのではなく、**重い計算から少しずつ** Rust の部品にします。

最終的には画面を含む全体の Rust 移行を目指します。移行中は既存の操作を維持し、
独立した計算部品、状態管理、画面の順に進めます。
シーク・表示切り替えの実装と計測は [display-performance.md](display-performance.md) に記録します。

**理由**

- 重い計算（PNG の読み書き、塗りつぶしの判定、色の集計など）は、Rust にすると
  速くなり、並列にもしやすくなります（Python の GIL の制約がありません）。
- 一方で、画面（Qt・PySide6 とドッキングの Qt Advanced Docking System）を
  一度に作り直すと、数か月は新しい機能を入れられなくなります。Rust から
  Qt Widgets とドッキングをそのまま使う手段もほぼありません。
- 大手のペイント・アニメソフト（Krita・OpenToonz・Photoshop など）も、
  中身はネイティブで、画面は Qt や独自の UI という分け方をしています。

**このため**

- Rust にする部品は「画像（配列）を受け取って結果を返す」だけの形にし、
  画面や Qt に触れさせません。画面を Rust へ移すときも、そのまま使えます。
- 新しく重い計算を書くときも、同じ形（画面から切り離した純粋な関数）で書き、
  あとで Rust へ移しやすくしておきます。
- Rust の部品が無い環境でも動くよう、当面は Python（numpy）版を残し、
  テストで両方が同じ結果になることを確かめます。
  ただし外部形式のコーデックは、上流ライブラリの保守を利用するためRustだけに置けます。
  CLIP読み込みは`clipfile-rs`を使い、独自のPythonパーサーは持ちません。
- 置き換える順番は、効果の大きいものからにします。塗りつぶしの判定（バケツ・
  ドラッグ塗り・串刺し塗りの追跡が共通で使う）、PNG の読み書き、色の集計・減色、
  セルの合成の順を目安にします。
- 操作したときの重さ（Undo やコマ移動の一拍）の多くは、タイムラインの表を毎回
  作り直していることが原因で、Rust にしても変わりません。こちらは変わったところ
  だけを更新するように直します。

### 画面まで Rust にするかの判断

画面（GUI）を Rust にする方式は、計算の部品化が進んでから決めます。候補は
Tauri（画面は HTML／JavaScript、中身は Rust）と egui ＋ egui_dock です。
決める前に、小さな試作で次の4点を確かめます。

- macOS と Windows の両方で、ペンタブレットの筆圧が取れるか
- 1920×1080 のキャンバスで、ブラシの遅れが今と同じか、それより小さいか
- 日本語入力（レイヤー名やスクリプト）が普通に使えるか
- パネルのフロート・ドッキング・タブ分割が、今と同じように使えるか

どれかが満たせないうちは、画面は Qt のままにします。
